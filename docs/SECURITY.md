# Безопасность LEADMEET OS

## Что защищаем
Базу лидов и переписку (персональные данные), доступы к каналам (почта, hh, Telegram, Claude), деньги и кредиты, репутацию аккаунтов и домена, целостность цифр для инвесторов.

## Меры
| Угроза | Защита |
|---|---|
| Подбор пароля | scrypt, лимит 10 попыток / 15 мин с IP и 20 / час на email, одинаковое время ответа для существующих и несуществующих email, 2FA (TOTP) |
| Кража сессии | Случайный токен 256 бит, в базе — только хеш; HttpOnly + SameSite=Lax + Secure (на HTTPS); выход на всех устройствах; смена пароля завершает все сессии |
| CSRF | Каждый изменяющий запрос — заголовок `x-csrf`, совпадающий с токеном сессии |
| Подмена IP в заголовках | `X-Forwarded-For` учитывается только при `TRUST_PROXY=true` (за своим Caddy/Nginx), берётся последний адрес |
| XSS | Весь текст экранируется (`esc`), ссылки — только http(s) через `safeUrl`; CSP `script-src 'self'` блокирует инлайн-скрипты и `javascript:` |
| SSRF при исследовании сайтов | Только http/https и стандартные порты; IP проверяется в момент соединения (нельзя обойти DNS-подменой); запрет локальных, служебных и IPv4-mapped IPv6 диапазонов; каждый редирект проверяется; таймаут и лимит размера |
| Инъекции в почту | Адреса проверяются строго, CR/LF в заголовках запрещены, тема кодируется base64 |
| Загрязнение прототипа | Ключи `__proto__/constructor/prototype` вырезаются из любого входа, слияние с ограничением глубины |
| ReDoS | Ограничение длины входа для регулярок, ограниченные квантификаторы в email-шаблонах |
| Доступ к чужим данным | Каждый документ привязан к кабинету сессии; смена кабинета — только при членстве; роли владелец / менеджер / клиент / наблюдатель |
| Секреты каналов | AES-256-GCM мастер-ключом; в интерфейсе видны только последние 3 символа; менеджер и клиент их не видят |
| Тихие правки задним числом | Журнал действий с хеш-цепочкой (как блокчейн): изменение любой прошлой записи ломает проверку |
| Потеря данных | Зашифрованные бэкапы по расписанию с ротацией, ручной бэкап, экспорт JSON, восстановление скриптом |
| Бан аккаунтов и домена | Дневные лимиты по каналам, прогрев почты, рабочее окно и паузы, отписка в один клик, ручная отправка с личных аккаунтов, капча — человеку |
| Злоупотребление кредитами | Кабинеты клиентов ограничены тарифом, кредиты только переводом из баланса родителя |
| Падение процесса | Перехват неожиданных ошибок с логированием; в проде — автоперезапуск (Docker `restart: always` / systemd) |

## Проверки
- Автотесты: `npm test` (включая CSRF, шифрование секретов, хеш-цепочку, бэкап и восстановление, SMTP-заголовки, права ролей, лимиты, SSRF-фильтр).
- Независимый red-team прогон и нагрузочный тест — результаты ниже.

## Результаты red-team (независимый агент, 4 ноября 2026) и что исправлено
| Уровень | Находка | Статус |
|---|---|---|
| Высокий | Инъекция заголовков и SMTP-команд через адрес получателя (CRLF → скрытый BCC) | Исправлено: строгая проверка email, запрет CR/LF во всех заголовках, проверка в API и при отправке; тесты |
| Высокий | Обход лимита входа подменой `X-Forwarded-For`; сброс всех счётчиков при 50 000 ключей | Исправлено: XFF только при `TRUST_PROXY=true`, лимит на email, вытеснение только старых ключей; тест |
| Высокий | Квадратичный разбор расшифровки: один запрос замораживал сервер на ~1 с | Исправлено: линейный алгоритм, лимит 300 000 символов и 6 000 реплик; тест (20 000 строк < 0,5 с) |
| Высокий | Список лидов и аналитика без пагинации: при 5 000 лидов 14–22 запроса/с, p99 до 22 с | Исправлено: сводки в отдельной колонке, кэш по версии кабинета, страница 300 и фильтры на сервере |
| Средний | Бесплатные кредиты: кабинеты с кредитами из воздуха, покупка пакета без оплаты на демо-сервере | Исправлено: лимит кабинетов по тарифу, кредиты только переводом, демо-покупка только в демо-кабинете; тесты |
| Средний | Наблюдатель видел ключи вебхуков и личные настройки | Исправлено: каналы и настройки — только владельцу, остальным урезанные настройки; тест |
| Средний | Перебор email: сообщение регистрации и разное время входа (×27) | Исправлено время входа (фиктивная проверка хеша). Регистрация: общий текст ошибки; полностью закрывается подтверждением email — остаточный риск, по умолчанию регистрация закрыта |
| Низкий | Кривые %-кодировки и cookie → 500 и стек в логе | Исправлено: 400/401; тест |
| Низкий | Глубоко вложенный JSON → переполнение стека | Исправлено: ограничение глубины слияния и разбора |
| Низкий | Ссылки `javascript:` в карточке (CSP уже блокировал) | Исправлено: только http(s) через `safeUrl` в интерфейсе и на сервере |
| Низкий | Пики CPU на огромных страницах и текстах стиля | Исправлено: лимиты 400 КБ на страницу, 60 КБ на текст стиля |
| Инфо | Ошибка почтового сервера → 500 | Исправлено: 502 с понятным текстом, письмо помечается «ошибка» |
| Инфо | SSRF через DNS-подмену (теоретически) | Исправлено: проверка IP в момент соединения |
| Инфо | Два процесса на одной базе задваивают рассылки | Исправлено: файл-замок, второй экземпляр не стартует |

Что агент проверил и не смог сломать: изоляция кабинетов (IDOR), CSRF, загрязнение прототипа, SSRF-фильтр, SQL-инъекции, границы ролей, сессии, токен отписки, блокировка отписавшихся, политика паролей и TOTP.

## Нагрузка (5 000 лидов, 2 000 писем, 300 сделок; 50 одновременных запросов, один процесс)
| Запрос | До исправлений | После |
|---|---|---|
| `/api/leads` | 14–22 запроса/с, p99 до 16,7 с | 440 запросов/с, p99 0,26 с (один запрос 5,6 мс) |
| `/api/analytics` | 10–18 запросов/с, p99 до 22 с | 2 418 запросов/с, p99 51 мс |
| `/api/counts` | — (раньше полная выгрузка) | 779 запросов/с |
| `/api/bootstrap` | 2 600 запросов/с | 940 запросов/с (теперь с проверкой ролей и урезанием настроек) |

Память процесса под нагрузкой — около 220 МБ. Для тысяч клиентов на одном сервере — горизонтальное масштабирование по кабинетам (отдельный процесс и база на группу кабинетов).
